operation_log table:
  ├─ op_id (transaction identifier)
  ├─ operation_type (create/update/delete/sync)
  ├─ entity_type (task/note/event/chat)
  ├─ entity_id (what changed)
  ├─ device_id (which device)
  ├─ status (success/failed/corrupted)
  ├─ error (failure details)
  ├─ retry_count (attempts)
  ├─ details (operation metadata)
  ├─ timestamp (when)
  └─ created_at (log entry time)

backup_log table:
  ├─ id (log entry id)
  ├─ operation (create/verify/restore/drill)
  ├─ backup_file (which backup)
  ├─ status (success/failed)
  ├─ details (metadata)
  └─ timestamp (when)

Both tables are backward compatible.
Existing data is not affected.
